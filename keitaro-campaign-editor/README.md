# Keitaro Campaign Editor — Часть 2: Редактор существующей кампании

Веб-сервис на FastAPI + SQLAlchemy (SQLite) и чистом HTML/JS для редактирования офферов в потоках существующей кампании Keitaro через Admin API v1.

## Что делает сервис

Позволяет выбрать существующую кампанию Keitaro (поиск по названию или ID, переход в админку по кнопке `View in KT`) и управлять офферами в её потоках:

1. **Загрузка потоков (`Fetch streams from KT`)** — подтягивает актуальные потоки кампании из Keitaro:
   * потоки **с офферами** отображаются сверху в виде редактируемых таблиц;
   * потоки **без офферов** (например, редирект по гео) выводятся компактной строкой внизу страницы;
   * если оффер был удалён напрямую в Keitaro, после `Fetch` он остаётся в таблице серым с долей `0%`, пометкой `(removed)` и кнопкой `Bring back`, а таблица остаётся белой (сохранённой).

2. **Локальный черновик и пересчёт долей** — добавление оффера через поиск с автокомплитом (`Add`), удаление (`Remove`), возврат (`Bring back`) и ручное изменение процента меняют только локальное состояние и автоматически пересчитывают доли. При наличии несохранённых изменений таблица становится жёлтой, появляются кнопки `Push to KT` и `Cancel`. Если вернуть состояние к исходному (например, удалить оффер и сразу нажать `Bring back`), таблица снова становится белой.

3. **Отправка на сервер (`Push to KT`)** — реальное обновление потока в Keitaro (`PUT /streams/{id}`) происходит только по нажатию `Push to KT`, после чего таблица снова становится белой.

4. **Закрепление процента (`📌`)** — фиксирует долю выбранного оффера, чтобы она не менялась при добавлении или удалении остальных (остаток от 100% равномерно делится между незакреплёнными активными офферами). Состояние булавки сохраняется локально в БД и не переводит таблицу в жёлтое (несохранённое) состояние.

## Быстрый запуск

### 1. Подготовка окружения

Требуется Python 3.10+.

```bash
# Создание и активация виртуального окружения (Windows PowerShell)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Для Linux / macOS:
# source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Скопируйте `.env.example` в `.env` и укажите доступы к вашему трекеру:

```bash
cp .env.example .env
```

**Обязательные параметры в `.env`:**

* `KEITARO_URL` — адрес трекера (например, `https://tlgk.host`)
* `KEITARO_API_KEY` — API-ключ из админки Keitaro

**Опциональные параметры** (имеют значения по умолчанию):

* `DATABASE_URL` — путь к БД (по умолчанию `sqlite:///./app.db`)
* `REQUEST_TIMEOUT` — таймаут запросов к Keitaro в секундах (по умолчанию `20`)
* `OFFERS_TTL_SECONDS` — время жизни локального кэша офферов в секундах (по умолчанию `300`)

### 3. База данных и миграции

В проекте используется локальная база данных **SQLite** (`app.db`) и ORM **SQLAlchemy** для трёх таблиц:

* `offers` — кэш офферов из Keitaro для быстрого автокомплита;
* `streams` — локальные снимки потоков кампаний;
* `stream_offers` — состояние офферов в потоках (доля `share`, флаги `is_pinned` и `is_removed`).

Отдельный инструмент миграций (например, Alembic) не требуется: **схема БД создаётся автоматически при старте приложения** (`app.db` появится в корне проекта после первого запуска).

Если нужно сбросить локальную базу, кэш офферов и историю удалённых записей, достаточно остановить сервер, удалить файл `app.db` и запустить приложение заново.

### 4. Запуск сервера

Из корня проекта выполните:

```bash
uvicorn app.main:app --reload
```

После запуска откройте в браузере: **http://127.0.0.1:8000**

## Запуск тестов

Тесты работают против локального мок-сервера Keitaro и in-memory SQLite и не требуют реального API-ключа.

Из корня проекта:

```bash
python -m pytest
```

Или через стандартный `unittest`:

```bash
python -m unittest discover -s tests -v
```
